# Техническое задание: мобильный одностраничный интернет-магазин клуба «СКАЗКА»

| Параметр | Значение |
|---|---|
| Заказчик | Спортивный клуб эстетической гимнастики «СКАЗКА» (сайт: https://skazka-ufa.ru/) |
| Продукт | Одностраничный интернет-магазин формы и атрибутики клуба (приём заказов) |
| Стек | HTML5, CSS3, Vanilla JavaScript (ES2017+), без фреймворков и сборщиков |
| Бэкенд | Google Apps Script (Web App) + Google Таблица |
| Приоритет платформы | Mobile-first (смартфоны 320–480 px), корректная работа на планшете и десктопе |
| Версия документа | 1.0 |

> **Условные обозначения.** В документе явно помечено:
> - **[Дано]** — взято из вводных заказчика или из файлов в папке Google Drive;
> - **[Решение]** — проектное решение исполнителя, которое заказчик может изменить;
> - **[Уточнить]** — сведения, которых нет во вводных. Их нужно подтвердить до начала или во время разработки (см. раздел 12).

---

## 1. Краткое описание продукта

Одностраничный мобильный магазин, где родители спортсменок (и взрослые занимающиеся) выбирают клубную форму и атрибутику. Для одежды выбирается размер, товары добавляются в корзину, затем оформляется заказ с указанием филиала клуба, где удобно получить товар.

Онлайн-оплаты в продукте нет. Заказ уходит в Google Таблицу через Google Apps Script, дальше его обрабатывает администратор клуба (связывается с клиентом, принимает оплату, выдаёт товар в филиале). **[Решение]** Способ оплаты и выдачи: **[Уточнить]**.

Ключевые свойства:
- одна страница: каталог → корзина → форма заказа;
- на мобильных оформление заказа идёт в одну колонку: **корзина сверху, форма снизу** **[Дано]**;
- фирменный стиль клуба: ярко-голубой, белый, акцентный розовый для кнопок **[Дано]**;
- корзина сохраняется между перезагрузками страницы (localStorage) **[Решение]**.

## 3. Функциональные требования

### 3.1. Шапка (Header)
- **FR-01.** В левом верхнем углу: логотип клуба и рядом текст белого цвета **«СКАЗКА Спортивный клуб эстетической гимнастики»** **[Дано]**. Фон шапки ярко-голубой (оттенок с учётом контраста, см. NFR-10).
- **FR-02.** Текст разбит на две строки: «СКАЗКА» (крупно, жирно) и «Спортивный клуб эстетической гимнастики» (мельче) **[Решение]**. Сам текст менять нельзя.
- **FR-03.** В правой части шапки иконка корзины со счётчиком товаров (сумма количеств). По нажатию страница плавно прокручивается к блоку корзины **[Решение]**.
- **FR-04.** Шапка закреплена сверху (`position: sticky`) **[Решение]**.

### 3.2. Каталог
- **FR-05.** Выводятся 13 товаров из массива `PRODUCTS` (раздел 5) в порядке ID.
- **FR-06.** Сетка каталога: 1 колонка при ширине < 360 px, 2 колонки от 360 px, 3 от 768 px, 4 от 1024 px **[Решение]**.
- **FR-07.** Структура карточки (сверху вниз) **[Дано]**:
  1. изображение товара (`images/{id}.jpg`);
  2. название товара **без цифр-номеров** (выводится поле `name`, в котором нет порядкового номера; ID на экране не показывается);
  3. крупная цена в формате `1 950 ₽`;
  4. выпадающий список размеров с плейсхолдером **«Выберите размер...»**, только если у товара есть размеры;
  5. тёмная кнопка **«В корзину»**.
- **FR-08.** Плейсхолдер «Выберите размер...» выбран по умолчанию, выбрать его как значение нельзя (`disabled`, `value=""`).
- **FR-09.** Если у товара один размер (товар 11: «L (48-50)»), список всё равно показывается, плейсхолдер остаётся выбранным по умолчанию **[Решение]**, чтобы покупатель явно подтвердил размер.
- **FR-10.** Нажатие «В корзину»:
  - если размеры есть, а размер не выбран: у списка появляется красная рамка и текст «Пожалуйста, выберите размер», фокус переходит на список, товар не добавляется;
  - иначе позиция добавляется в корзину (или её количество растёт на 1, если такая пара «товар + размер» уже есть), кнопка на 1,5 с показывает «Добавлено ✓», счётчик в шапке обновляется.
- **FR-11.** Изображения грузятся лениво (`loading="lazy"`), с фиксированным соотношением сторон (`aspect-ratio: 1 / 1`, `object-fit: cover`), чтобы вёрстка не «прыгала».

### 3.3. Корзина
- **FR-12.** Корзина стоит над формой заказа (одна колонка на мобильных) **[Дано]**. На ширине ≥ 1024 px допускаются две колонки: корзина слева, форма справа **[Решение]**.
- **FR-13.** Каждая позиция корзины: миниатюра, название, размер (если есть), цена за единицу, контрол количества «− N +», сумма по позиции, кнопка удаления «×».
- **FR-14.** Количество от 1 до 10 на позицию **[Решение]**. «−» при количестве 1 неактивна, удаление только через «×».
- **FR-15.** Внизу корзины: общее количество товаров и **итоговая сумма** (крупно).
- **FR-16.** Пустая корзина: текст «Корзина пуста. Добавьте товары из каталога» и ссылка-якорь к каталогу. Кнопка отправки заказа неактивна.
- **FR-17.** Корзина сохраняется в `localStorage` под ключом `skazka_cart_v1` и восстанавливается при загрузке. При восстановлении позиции сверяются с актуальным `PRODUCTS` (см. EC-09, EC-10).

### 3.4. Форма оформления заказа
- **FR-18.** Поля формы:

| Поле | Тип | Обязательное | Правила валидации |
|---|---|---|---|
| ФИО покупателя (родителя) | text | да | 2–100 символов, только буквы (кириллица и латиница), пробел, дефис; после `trim` не пустое |
| Телефон | tel | да | маска `+7 (XXX) XXX-XX-XX`; ровно 11 цифр, первая 7 (ввод «8…» автоматически превращается в «+7…») |
| ФИО ребёнка (спортсменки) | text | да **[Уточнить]** | те же правила, что для ФИО покупателя |
| Филиал | select | да | значение из списка 13 филиалов, плейсхолдер «Выберите филиал...» |
| Комментарий | textarea | нет | до 500 символов, счётчик символов |
| Согласие на обработку персональных данных | checkbox | да | должно быть отмечено; ссылка на политику **[Уточнить]**: текст политики предоставляет заказчик |

- **FR-19.** Список филиалов (select), порядок как во вводных **[Дано]**:
  1. ЦСП Мустафина
  2. Затон
  3. Садик 144
  4. Дёма
  5. ШВСМ
  6. Башлицей 2
  7. Кузнецовский Затон
  8. Медунивер
  9. Новошкола
  10. Динамо
  11. Центр гимнастики
  12. Дворец борьбы
  13. Нефтяник

  > Точные почтовые адреса филиалов во вводных не указаны. Выводятся только названия. Если нужны адреса, **[Уточнить]** у заказчика.

- **FR-20.** Валидация идёт при потере фокуса (`blur`) и при отправке. Ошибка показывается под полем красным текстом, у поля появляется `aria-invalid="true"`. При отправке с ошибками фокус и прокрутка переходят к первому невалидному полю.
- **FR-21.** Кнопка **«Оформить заказ»** акцентного розового цвета, во всю ширину, с итоговой суммой на кнопке: «Оформить заказ · 5 850 ₽» **[Решение]**.
- **FR-22.** При отправке кнопка блокируется, показывает спиннер и текст «Отправляем...». Повторная отправка невозможна до получения ответа (защита от двойного клика).
- **FR-23.** Ответ успешный (`ok: true`): показывается экран подтверждения с номером заказа (раздел 7, экран 4), корзина и форма очищаются, `localStorage` сбрасывается.
- **FR-24.** Ошибка сети, таймаут (15 с) или `ok: false`: корзина и данные формы **сохраняются**, показывается сообщение об ошибке с кнопкой «Повторить» (раздел 8).
- **FR-25.** Черновик формы (кроме чекбокса согласия) сохраняется в `localStorage` под ключом `skazka_form_v1` **[Решение]** и очищается после успешной отправки.

### 3.5. Номер заказа
- **FR-26.** Номер заказа генерирует **сервер** (Apps Script) в формате `SK-YYMMDD-NNN`, где `NNN` — порядковый номер заказа за день с ведущими нулями (например, `SK-260927-004`) **[Решение]**.
- **FR-27.** Клиент дополнительно генерирует `clientOrderId` (UUID v4 через `crypto.randomUUID()`, запасной вариант: `Date.now()` + `Math.random()`) для защиты от дублей при повторной отправке (EC-14).

## 4. Нефункциональные требования

### 4.1. Производительность
- **NFR-01.** Первая отрисовка (FCP) до 2 с на эмулированном «Slow 4G» (Lighthouse, Moto G Power).
- **NFR-02.** Lighthouse Mobile: Performance ≥ 85, Accessibility ≥ 90, Best Practices ≥ 90, SEO ≥ 90.
- **NFR-03.** Каждое изображение товара не больше 150 КБ, 800×800 px. Исходники в Google Drive — PNG по 1,5–2,1 МБ (**[Дано]**, см. 6.6), поэтому их нужно конвертировать и сжать (JPG, качество ~80). Логотип (`logo.png`, исходник ~1,1 МБ **[Дано]**) нужно сжать до ≤ 50 КБ или заменить на SVG, если он есть у заказчика **[Уточнить]**.
- **NFR-04.** Суммарный вес HTML + CSS + JS без изображений не больше 100 КБ (без минификации). Внешних JS-библиотек нет.

### 4.2. Совместимость
- **NFR-05.** Поддерживаемые браузеры: Safari iOS 14+, Chrome Android 90+, Samsung Internet 14+, Яндекс Браузер (актуальный), Chrome / Firefox / Safari / Edge для десктопа (последние 2 версии).
- **NFR-06.** Минимальная ширина экрана 320 px, без горизонтальной прокрутки.

### 4.3. UI и брендинг
- **NFR-07.** Цветовая палитра задаётся CSS-переменными в `:root`. Точные HEX-коды фирменных цветов во вводных не указаны, поэтому ниже предлагаемые значения **[Уточнить]** (заменить на брендбук, если он есть):

```css
:root {
  --color-primary: #1EA7E1;      /* ярко-голубой: шапка, акценты, ссылки [Уточнить HEX] */
  --color-primary-dark: #1587B8; /* голубой при нажатии/наведении */
  --color-white: #FFFFFF;        /* фон карточек, текст в шапке */
  --color-accent: #FF4FA3;       /* акцентный розовый: главная кнопка «Оформить заказ» [Уточнить HEX] */
  --color-accent-dark: #E0338A;
  --color-dark: #1F2430;         /* тёмная кнопка «В корзину», основной текст */
  --color-bg: #F2F9FD;           /* фон страницы (светло-голубой) */
  --color-error: #D93025;
  --color-success: #1E8E3E;
  --radius: 12px;
}
```

- **NFR-08.** Кнопки и интерактивные элементы не меньше 44×44 px (touch target).
- **NFR-09.** Шрифт: системный стек (`-apple-system, "Segoe UI", Roboto, Arial, sans-serif`) **[Решение]**, без загрузки веб-шрифтов. Базовый размер текста 16 px (иначе iOS увеличивает страницу при фокусе на поле).

### 4.4. Доступность (a11y)
- **NFR-10.** Контраст текста не ниже WCAG 2.1 AA: 4.5:1 для обычного текста, 3:1 для крупного (≥ 24 px или ≥ 18.66 px bold). Расчёт по формуле WCAG для предложенных цветов:
  - белый на `#1EA7E1` ≈ 2.74:1, не проходит даже порог для крупного текста;
  - белый на `#1587B8` ≈ 4.05:1, проходит только для крупного текста;
  - белый на `#FF4FA3` ≈ 3.04:1, подходит только для крупного жирного текста (текст кнопки делать ≥ 18.66 px bold);
  - белый на `#1F2430` ≈ 15.5:1, проходит.

  Поэтому фон шапки под белым текстом — не светлее `--color-primary-dark`, а текст «Спортивный клуб эстетической гимнастики» — не мельче 18.66 px bold, или нужен ещё более тёмный оттенок голубого. Итоговые оттенки согласовать с заказчиком **[Уточнить]**.
- **NFR-11.** У всех полей есть `<label>`, у изображений `alt` с названием товара, у списка размеров `aria-label="Размер: {название}"`. Сообщения о добавлении в корзину и ошибках отправки дублируются в `aria-live="polite"`.
- **NFR-12.** Всё управляется с клавиатуры, фокус виден.

### 4.5. Безопасность и данные
- **NFR-13.** Сайт работает по HTTPS.
- **NFR-14.** Весь пользовательский ввод выводится через `textContent` (без `innerHTML`). На сервере значения, начинающиеся с `=`, `+`, `-`, `@`, экранируются апострофом (защита от formula injection в Google Таблице).
- **NFR-15.** Цены на сервере **пересчитываются** по серверной копии каталога. Цена от клиента не считается достоверной.
- **NFR-16.** Персональные данные хранятся только в Google Таблице с доступом для администраторов клуба. В `localStorage` лежит только черновик формы на устройстве пользователя.
- **NFR-17.** Скрытое поле-ловушка (honeypot) `website` против ботов: если оно заполнено, сервер отвечает `ok: true`, но строку не записывает.

## 6. Интеграции: Google Apps Script

### 6.1. Архитектура

```
[Браузер] --POST (text/plain, JSON)--> [Apps Script Web App: doPost]
                                             │ валидация, пересчёт цен
                                             │ LockService
                                             ▼
                                   [Google Таблица, лист «Заказы»]
[Браузер] <--JSON {ok, orderId}------------- ┘
```

### 6.2. Google Таблица
- Файл: «СКАЗКА — Заказы магазина» **[Решение]**.
- Лист `Заказы`: **одна строка = одна позиция заказа**. Заказ из 3 позиций занимает 3 строки с одинаковым номером заказа **[Решение]**. Так администратор может фильтровать и сводить данные по товару и размеру (например, «сколько леггинсов размера 30 заказать у поставщика»).
- Лист `Log` хранит технические ошибки сервера.
- Первая строка листа `Заказы` содержит заголовки, закреплена и защищена от редактирования.

### 6.3. Строгий порядок колонок листа `Заказы`

> Порядок колонок **фиксирован**. Сервер пишет строку массивом строго в этом порядке через `appendRow`. Переставлять, вставлять или удалять колонки в таблице **запрещено**: это сломает запись. Новые колонки добавляются **только справа** (после `O`), одновременно с изменением `Code.gs`.

| № | Колонка | Заголовок | Тип / формат | Источник | Пример |
|---|---|---|---|---|---|
| 1 | A | Дата и время | `dd.MM.yyyy HH:mm:ss`, часовой пояс Asia/Yekaterinburg (Уфа, UTC+5) | сервер (`new Date()`) | 27.09.2026 15:15:30 |
| 2 | B | Номер заказа | строка `SK-YYMMDD-NNN` | сервер | SK-260927-004 |
| 3 | C | ФИО покупателя | строка | `customer.name` | Иванова Анна Сергеевна |
| 4 | D | Телефон | строка `+7XXXXXXXXXX` (с ведущим апострофом, чтобы Таблица не превратила номер в число или формулу) | `customer.phone` | +79171234567 |
| 5 | E | ФИО ребёнка | строка | `customer.childName` | Иванова Мария |
| 6 | F | Филиал | строка из списка BRANCHES | `customer.branch` | Затон |
| 7 | G | ID товара | число 1–13 | `items[i].productId` | 1 |
| 8 | H | Товар | строка (название из серверного каталога) | сервер | Лонгслив детский черный «Сказка» |
| 9 | I | Размер | строка; `—`, если размера нет | `items[i].size` | 128-134 |
| 10 | J | Цена за шт., ₽ | число | сервер (каталог) | 1950 |
| 11 | K | Кол-во | число 1–10 | `items[i].qty` | 1 |
| 12 | L | Сумма позиции, ₽ | число = J × K | сервер | 1950 |
| 13 | M | Итого по заказу, ₽ | число (одинаково во всех строках заказа) | сервер | 3130 |
| 14 | N | Комментарий | строка до 500 символов | `customer.comment` | Позвоните после 18:00 |
| 15 | O | Статус | строка; при создании `Новый` | сервер | Новый |

Скрытая служебная колонка **P — `clientOrderId`** пишется справа от `O` (для защиты от дублей, EC-14). Колонку `O` администратор меняет вручную через выпадающий список (проверка данных): `Новый` / `В работе` / `Оплачен` / `Выдан` / `Отменён` **[Решение]**.

### 6.4. Серверный код (эталон для `Code.gs`)

```javascript
const SHEET_NAME = 'Заказы';
const TZ = 'Asia/Yekaterinburg';

// Серверная копия каталога: источник истины для цен и размеров.
const CATALOG = {
  1:  { name: 'Лонгслив детский черный «Сказка»', price: 1950, sizes: ['104-110','116-122','128-134','140-146','152-158'] },
  // … товары 2–13, полностью совпадающие с js/data.js
};
const BRANCHES = ['ЦСП Мустафина','Затон','Садик 144','Дёма','ШВСМ','Башлицей 2',
  'Кузнецовский Затон','Медунивер','Новошкола','Динамо','Центр гимнастики','Дворец борьбы','Нефтяник'];

function doPost(e) {
  const lock = LockService.getScriptLock();
  try {
    const data = JSON.parse(e.postData.contents);
    if (data.website) return json({ ok: true, orderId: 'SK-000000-000' }); // honeypot

    const errors = validate(data);               // поля, телефон, филиал, товары, размеры, qty
    if (errors.length) return json({ ok: false, error: 'VALIDATION_ERROR', message: errors.join('; ') });

    if (!lock.tryLock(10000)) return json({ ok: false, error: 'LOCK_TIMEOUT', message: 'Сервер занят, повторите' });

    const sheet = SpreadsheetApp.getActive().getSheetByName(SHEET_NAME);
    const dup = findByClientOrderId(sheet, data.clientOrderId);   // поиск в колонке P
    if (dup) return json({ ok: true, orderId: dup.orderId, total: dup.total, duplicate: true });

    const now = new Date();
    const orderId = nextOrderId(sheet, now);    // SK-YYMMDD-NNN
    const lines = data.items.map(it => {
      const p = CATALOG[it.productId];
      return { ...it, name: p.name, price: p.price, sum: p.price * it.qty };
    });
    const total = lines.reduce((s, l) => s + l.sum, 0);
    const ts = Utilities.formatDate(now, TZ, 'dd.MM.yyyy HH:mm:ss');
    const c = data.customer;

    // СТРОГИЙ ПОРЯДОК КОЛОНОК A–P (см. ТЗ, раздел 6.3)
    lines.forEach(l => sheet.appendRow([
      ts,                        // A Дата и время
      orderId,                   // B Номер заказа
      safe(c.name),              // C ФИО покупателя
      "'" + c.phone,             // D Телефон
      safe(c.childName),         // E ФИО ребёнка
      c.branch,                  // F Филиал
      l.productId,               // G ID товара
      l.name,                    // H Товар
      l.size || '—',             // I Размер
      l.price,                   // J Цена за шт.
      l.qty,                     // K Кол-во
      l.sum,                     // L Сумма позиции
      total,                     // M Итого по заказу
      safe(c.comment || ''),     // N Комментарий
      'Новый',                   // O Статус
      data.clientOrderId,        // P clientOrderId (служебная)
    ]));
    SpreadsheetApp.flush();
    return json({ ok: true, orderId, total });
  } catch (err) {
    logError(err);
    return json({ ok: false, error: 'SERVER_ERROR', message: 'Внутренняя ошибка сервера' });
  } finally {
    lock.releaseLock();
  }
}

function safe(v) { v = String(v).trim(); return /^[=+\-@]/.test(v) ? "'" + v : v; }
function json(obj) {
  return ContentService.createTextOutput(JSON.stringify(obj)).setMimeType(ContentService.MimeType.JSON);
}
```

`validate`, `findByClientOrderId`, `nextOrderId`, `logError` реализует исполнитель по правилам из разделов 3.4, 5 и 6.3.

### 6.5. Вызов с клиента

```javascript
const API_URL = 'https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec';

async function sendOrder(payload) {
  const ctrl = new AbortController();
  const timer = setTimeout(() => ctrl.abort(), 15000);
  try {
    const res = await fetch(API_URL, {
      method: 'POST',
      // text/plain — «простой» запрос без CORS preflight (Apps Script не отвечает на OPTIONS)
      headers: { 'Content-Type': 'text/plain;charset=utf-8' },
      body: JSON.stringify(payload),
      signal: ctrl.signal,
      redirect: 'follow',
    });
    return await res.json();
  } finally {
    clearTimeout(timer);
  }
}
```

### 6.6. Развёртывание и подготовка данных
1. Создать Google Таблицу, лист `Заказы` с заголовками A–O (+ P) строго по 6.3, лист `Log`.
2. «Расширения → Apps Script», вставить `Code.gs`, в настройках проекта задать часовой пояс `Asia/Yekaterinburg`.
3. «Развернуть → Новое развертывание → Веб-приложение»: *Выполнять от имени:* **Я** (владелец таблицы); *Доступ:* **Все** (Anyone).
4. URL развертывания (`…/exec`) записать в `API_URL` в `js/data.js`.
5. После **любого** изменения `Code.gs` выпустить новую версию в *том же* развертывании («Управление развертываниями → Изменить → Новая версия»), иначе URL изменится или старый код продолжит работать.
6. **Изображения [Дано → требует подготовки]:** в папке Google Drive файлы названы как `«{N} {Название}.png»` (например, `1 Лонгслив детский черный “Сказка”.png`), логотип лежит в `logo.png`. Сайт ожидает `images/{id}.jpg`, поэтому каждый файл `N …png` нужно переименовать в `N.jpg` с конвертацией PNG → JPG и сжатием (NFR-03). Если нужна прозрачность, альтернатива — оставить PNG и поменять шаблон пути на `images/{id}.png` **[Уточнить]**.

### 6.7. Уведомления (вне MVP)
Опционально: триггер `onFormSubmit` не подходит, поэтому в конце `doPost` вызывается `MailApp.sendEmail` или Telegram Bot API для оповещения администратора о новом заказе. Адресат и канал: **[Уточнить]**.

## 8. Edge cases и ошибки

| ID | Ситуация | Ожидаемое поведение |
|---|---|---|
| EC-01 | «В корзину» нажата без выбора размера | Товар не добавляется, красная рамка у select, текст «Пожалуйста, выберите размер», фокус на select. Ошибка исчезает после выбора размера |
| EC-02 | Один и тот же товар с тем же размером добавлен повторно | Новая строка не создаётся, количество существующей позиции растёт на 1 |
| EC-03 | Один товар в двух разных размерах | Две отдельные позиции в корзине и две строки в таблице |
| EC-04 | Количество позиции достигло 10 | «+» неактивна, при добавлении из каталога тост «Максимум 10 шт. одной позиции» |
| EC-05 | Отправка с пустой корзиной | Кнопка «Оформить заказ» неактивна. Если запрос всё же пришёл (например, из консоли), сервер отвечает `EMPTY_CART` |
| EC-06 | Телефон неполный или начинается не с 7/8 | Ошибка «Введите номер в формате +7 (XXX) XXX-XX-XX», отправка блокируется |
| EC-07 | ФИО из пробелов, цифр или спецсимволов | Ошибка «Введите имя и фамилию буквами». После `trim` пустые строки не допускаются |
| EC-08 | Филиал не выбран | Ошибка «Выберите филиал», фокус на select |
| EC-09 | В `localStorage` лежит позиция с несуществующим ID товара (товар убран из каталога) | Позиция молча удаляется из корзины при загрузке, показывается тост «Некоторые товары больше недоступны и удалены из корзины» |
| EC-10 | В `localStorage` лежит позиция с размером, которого больше нет у товара | Позиция удаляется, тот же тост |
| EC-11 | `localStorage` недоступен (приватный режим Safari, квота, запрет cookies) или содержит невалидный JSON | Все обращения обёрнуты в `try/catch`. Корзина работает в памяти, приложение не падает. Невалидный JSON сбрасывается |
| EC-12 | Нет интернета при отправке (`navigator.onLine === false` или `TypeError: Failed to fetch`) | Сообщение «Нет соединения с интернетом. Проверьте сеть и нажмите “Повторить”». Корзина и форма сохраняются |
| EC-13 | Сервер не ответил за 15 с | Запрос отменяется (`AbortController`), сообщение «Сервер не отвечает. Попробуйте ещё раз». Данные сохраняются |
| EC-14 | Повторная отправка того же заказа (двойной тап, «Повторить» после таймаута, хотя заказ уже записан) | Кнопка блокируется на время запроса. При повторе отправляется **тот же** `clientOrderId`, сервер находит его в колонке P и возвращает уже созданный `orderId` без новой записи |
| EC-15 | Сервер вернул `ok: false` / `VALIDATION_ERROR` | Показывается `message` от сервера или общий текст «Не удалось оформить заказ. Проверьте данные». Корзина сохраняется |
| EC-16 | Сервер вернул не JSON (HTML-страница ошибки Google, развертывание удалено, нет доступа) | `res.json()` падает, ловится исключение: «Сервис заказов временно недоступен. Позвоните администратору клуба» + контакт **[Уточнить]** |
| EC-17 | Цена у клиента устарела (кэш страницы, старая версия `data.js`) | Сервер пишет в таблицу серверные цены и возвращает актуальный `total`. Если `total ≠ clientTotal`, окно подтверждения показывает итог с сервера и пометку «Сумма пересчитана по актуальным ценам» |
| EC-18 | Картинка товара не загрузилась (404, файл не переименован) | Обработчик `onerror` подменяет изображение на `images/placeholder.svg`, вёрстка карточки не ломается |
| EC-19 | Два заказа одновременно | `LockService` сериализует запись. Номера `NNN` не дублируются. Если блокировку не удалось получить за 10 с, ответ `LOCK_TIMEOUT` и клиент предлагает повторить |
| EC-20 | Ввод, похожий на формулу (`=HYPERLINK(...)`, `+7...` в комментарии) | Сервер экранирует начальным апострофом (NFR-14), в таблице значение отображается как текст |
| EC-21 | Бот заполнил honeypot `website` | Сервер отвечает «успехом», строка не пишется |
| EC-22 | Очень длинное название товара или комментарий | Название обрезается многоточием после 3 строк (`-webkit-line-clamp`), комментарий ограничен 500 символами (`maxlength` + серверная проверка) |
| EC-23 | Экран 320 px или поворот в landscape | Нет горизонтального скролла, карточки перестраиваются по сетке FR-06 |
| EC-24 | Автозаполнение браузера подставило телефон в формате `89171234567` или `+7 917 123 45 67` | Маска нормализует значение к `+7 (917) 123-45-67` и проходит валидацию |
